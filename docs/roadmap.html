🧠 Knowledge check — 3 quick questions
1. What is the main difference between convolution and cross-correlation?
✅ Convolution flips (rotates 180 degrees) the kernel before the sliding dot product, whereas cross-correlation applies the kernel as-is; for symmetric kernels the results are identical.
2. Histogram equalization is primarily used to:
✅ It remaps intensities so the output histogram is roughly uniform, stretching contrast across the available range.
3. In PCA, the principal directions of the data correspond to the:
✅ PCA finds the eigenvectors of the data's covariance matrix, ordered by eigenvalue (variance explained).

🧠 Knowledge check — 3 quick questions
1. Why is RANSAC used when estimating a homography from matched features?
✅ Feature matches contain many wrong correspondences; RANSAC repeatedly fits from minimal samples and keeps the hypothesis with the most inliers, ignoring outliers.
2. Which property makes SIFT descriptors useful across different photos of the same scene?
✅ SIFT detects keypoints across scales and assigns a dominant orientation, making its descriptors robust to scale and in-plane rotation.
3. A homography can exactly map between two images when:
✅ A homography is a planar projective transform, valid for planar scenes or pure-rotation camera motion; general 3D scenes with translation need epipolar geometry.

🧠 Knowledge check — 3 quick questions
1. The epipolar constraint x'^T F x = 0 means that:
✅ The fundamental matrix maps a point in one image to its epipolar line in the other, reducing the correspondence search from 2D to 1D.
2. In a rectified stereo pair, depth is related to disparity how?
✅ Depth = (focal length x baseline) / disparity, so larger disparity (more shift) means a closer, smaller-depth point.
3. What does bundle adjustment optimize?
✅ Bundle adjustment is a joint nonlinear refinement of all poses and structure that minimizes the sum of reprojection errors across all observations.
🏆 Milestone Project

Two-View Structure-from-Motion (Sparse 3D Reconstruction)

Take two photos of a static scene and get the intrinsics K from calibration (Phase 2) or image EXIF. Match SIFT/ORB features, estimate the fundamental matrix with the normalized 8-point algorithm inside RANSAC, convert it to the essential matrix (E = K′ᵀ F K), and decompose E into its four candidate (R, t) solutions. Use the cheirality check — reconstructed points must lie in front of both cameras — to pick the correct pose, then triangulate the matches into a sparse 3D point cloud and visualize it. No high-level SfM pipelines (e.g. COLMAP) for the core estimation.

🧠 Knowledge check — 3 quick questions
1. At an IoU threshold of 0.5, a predicted box counts as a true positive when:
✅ A detection is a true positive when its IoU with a same-class ground-truth box meets the threshold (here 0.5).
2. What problem does Non-Maximum Suppression solve?
✅ NMS keeps the highest-scoring box and removes others with high IoU overlap, collapsing duplicate detections of one object.
3. Why do ResNet skip connections help train very deep networks?
✅ Residual shortcuts add the input to the output, providing an identity path that mitigates vanishing gradients and degradation in deep nets.

🧠 Knowledge check — 3 quick questions
1. How does a Vision Transformer first turn an image into tokens?
✅ ViT divides the image into fixed-size patches and linearly embeds each into a token vector, then adds positional encodings.
2. What is the core training objective of CLIP?

✅ INT8 quantization lowers numeric precision to shrink memory and accelerate inference on edge hardware, usually with minor accuracy loss.

💼 Interview Prep Bank

CV-specific theory, implementation, math, and system-design questions with hints

AllTheoryImplementationSystem DesignDebuggingMath
Theory

Why does ResNet use skip connections?

Hint: Vanishing gradients + identity shortcuts let very deep networks train without degradation.

Implementation

Implement IoU from scratch in NumPy

Hint: intersection = max(0, x2−x1) × max(0, y2−y1). Union = A + B − intersection.

System Design

Design a real-time pedestrian detector for a city intersection camera

Hint: Consider latency SLA, edge vs. cloud, model selection, failure modes, and demographic bias.

Theory

How does attention differ from convolution?

Hint: Conv = local fixed receptive field. Attention = global, dynamic weight per token pair.

Debugging

Your detector has high precision but low recall. What's wrong?

Hint: Confidence threshold too high. Lower it and re-examine the precision-recall curve.

Implementation

Explain NMS and implement it in Python

Hint: Sort by confidence, suppress overlapping boxes (IoU > threshold), keep highest-confidence box.

Math

Derive the epipolar constraint and explain why the fundamental matrix has rank 2.

Hint: Start from x'^T F x = 0. F maps a point to a line; the epipole is the right null-vector (Fe = 0), which forces det(F)=0, hence rank 2 (7 DoF).

Theory

What is the difference between the fundamental matrix and the essential matrix, and when would you use each?

Hint: E operates on calibrated (normalized) coordinates and relates to relative R and t (E = [t]_x R, 5 DoF); F works on uncalibrated pixel coordinates (E = K'^T F K). Use F when intrinsics are unknown, E to recover pose.

Implementation

Walk through estimating a fundamental matrix from point correspondences with RANSAC, including how you normalize points and count inliers.

Hint: Hartley normalization (translate/scale points), 8-point (or 7-point) algorithm inside RANSAC, score inliers by Sampson distance to the epipolar line, then re-fit on the consensus set.

Math

Given a rectified stereo pair with focal length f, baseline B, and disparity d at a pixel, compute the depth Z and discuss the precision implications of baseline choice.

Hint: Z = f*B/d. Depth error grows with Z^2 and shrinks with larger B; but a wider baseline reduces image overlap and makes matching harder, so it is a trade-off.

Theory

Explain triangulation for a 3D point seen in two calibrated views and why the linear DLT solution is only approximate.

Hint: Back-project rays from both cameras; ideally they intersect, but noise means they don't, so DLT solves a homogeneous least-squares (SVD) system. The optimal estimate minimizes reprojection error, often refined nonlinearly.

System Design

Design a visual SLAM system for an indoor delivery robot using a single camera. What are the main modules and failure modes?

Hint: Front-end (feature/optical-flow tracking, pose via PnP), back-end (local bundle adjustment / pose graph), keyframing, loop closure, relocalization. Failure modes: scale drift (monocular), low-texture walls, motion blur, dynamic objects.

Debugging

Your SfM reconstruction produces a warped, scale-inconsistent point cloud. How do you diagnose and fix it?

Hint: Check feature match outliers and geometric verification, inspect reprojection error per camera, verify calibration/intrinsics, ensure enough baseline between views (degenerate pure-rotation), and run/tune bundle adjustment; fix scale with a known reference or loop closure.

Implementation

Implement bilinear interpolation for image warping and explain where it is needed in a homography-based panorama stitcher.

Hint: For each output pixel, inverse-map through H^-1 to a fractional source location, then blend the four neighboring pixels by their distances. Needed because warped coordinates rarely land on integer pixel grid positions.

Theory

Compare anchor-based detectors (Faster R-CNN, SSD) with anchor-free approaches. What problems do anchors introduce?

Hint: Anchors add hyperparameters (scales/ratios), cause foreground-background imbalance, and complicate matching. Anchor-free methods (e.g. center/keypoint-based) predict boxes directly, simplifying the pipeline at some cost to certain shapes.

Debugging

A semantic segmentation model scores high mean IoU on validation but produces noisy, fragmented masks at inference. What would you check?

Hint: Train/inference preprocessing mismatch (normalization, input size), class imbalance inflating mIoU via easy classes, missing CRF/post-processing, domain shift, and whether mIoU is dominated by background; visualize per-class IoU and raw logits.

Math

Explain why self-attention is O(n^2) in sequence length and what that means for high-resolution images in a ViT.

Hint: Each of n tokens attends to all n tokens, giving an n x n score matrix. For images, n scales with the number of patches, so high resolution explodes compute/memory; mitigations include windowed attention (Swin) or fewer/larger patches.

System Design

Design a stereo-camera depth perception pipeline for an autonomous drone running on an embedded GPU. Cover calibration, runtime, and edge constraints.

Hint: Offline stereo calibration + rectification maps, real-time matching (SGBM or a quantized stereo net), disparity-to-depth, temporal filtering; constraints: INT8/FP16 quantization, fixed resolution, latency budget, and graceful degradation in low texture or glare.

📖 Glossary

52 key terms across all five phases, in plain English

All1 · Foundations2 · Classical CV3 · Geometry & 3D4 · Deep Learning5 · Frontiers
Color space P1
A coordinate system describing colors numerically; RGB stores additive channels, HSV separates hue/saturation/value, and LAB approximates perceptual differences.
Convolution P1
Sliding a small kernel over an image and computing a weighted sum at each position; the core operation behind blurring, edge detection, and CNNs.
Cross-correlation P1
Same sliding-window dot product as convolution but without flipping the kernel; what deep learning libraries actually compute and loosely call 'convolution'.
Eigenvector / Eigenvalue P1
A vector whose direction is unchanged by a matrix (only scaled by the eigenvalue); the basis of PCA and of corner-response analysis.
FFT (Fast Fourier Transform) P1
An efficient algorithm to convert an image into its frequency components, exposing periodic patterns and enabling frequency-domain filtering.
Gradient P1
The vector of partial derivatives of intensity (or a loss) with respect to its inputs; points in the direction of steepest increase and underlies edge detection and backprop.
Histogram equalization P1
A contrast-enhancement technique that remaps pixel intensities so the output histogram is roughly uniform, spreading values across the full range.
Kernel (filter) P1
A small matrix of weights (e.g. 3x3) convolved with an image to produce effects like smoothing, sharpening, or gradient estimation.
Morphological operations P1
Shape-based operations on binary/grayscale images using a structuring element; erosion shrinks regions, dilation grows them, and openings/closings clean up noise.
Pixel P1
The smallest addressable element of a digital image, holding one intensity value (grayscale) or several channel values (e.g. R, G, B).
Bag of Visual Words P2
Represents an image as a histogram of quantized local descriptors (visual 'words') from a learned codebook, enabling classic image retrieval/classification.
Camera calibration P2
Estimating a camera's intrinsics (focal length, principal point) and lens distortion, typically via Zhang's method using multiple views of a checkerboard.
Canny edge detector P2
A multi-stage edge pipeline: Gaussian smoothing, gradient computation, non-maximum suppression, then hysteresis thresholding for clean thin edges.
Harris corner detector P2
Finds corners by analyzing the eigenvalues of the local gradient (structure) tensor; large in two directions means a stable corner.
HOG P2
Histogram of Oriented Gradients: describes local shape by binning gradient directions over a grid of cells; classic input to pedestrian detectors.
Homography P2
A 3x3 projective transform mapping one plane to another between two images; used for panorama warping, document rectification, and planar AR.
Optical flow P2
The per-pixel apparent motion between consecutive frames; Lucas-Kanade solves it locally assuming brightness constancy and small motion.
ORB P2
Oriented FAST and Rotated BRIEF: a fast, patent-free binary feature detector/descriptor matched with Hamming distance, popular for real-time and SLAM use.
RANSAC P2
Random Sample Consensus: robustly fits a model (e.g. homography) by repeatedly sampling minimal point sets and keeping the hypothesis with the most inliers.
SIFT P2
Scale-Invariant Feature Transform: detects keypoints across scales and describes each with a 128-D gradient-orientation histogram robust to scale and rotation.
Baseline P3
The distance between the two camera centers in a stereo rig; a wider baseline improves depth precision but reduces overlap and matchable area.
Bundle adjustment P3
Joint nonlinear refinement of all camera poses and 3D points by minimizing total reprojection error; the optimization backbone of SfM and SLAM.
Disparity P3
The horizontal pixel shift of a point between left and right rectified stereo images; inversely proportional to depth.
Epipolar line P3
The line in one image along which the match of a given point in the other image must lie, constraining stereo correspondence search to 1D.
Epipole P3
The point in one image where the other camera's center projects; all epipolar lines in that image pass through it.
Essential matrix P3
The calibrated analog of the fundamental matrix (E = K'^T F K); it relates normalized image coordinates and decomposes into the relative rotation and translation.
Fundamental matrix P3
A 3x3 rank-2 matrix encoding the epipolar geometry between two uncalibrated views: x'^T F x = 0 for any corresponding image points x and x'.
PnP (Perspective-n-Point) P3
Estimating a calibrated camera's pose (rotation and translation) from n known 3D points and their 2D image projections.
Point cloud P3
An unordered set of 3D points (often with color/normals) representing a scene's surface, produced by stereo, depth sensors, or SfM/SLAM.
Reprojection error P3
The pixel distance between an observed feature and where its estimated 3D point projects into the image; the standard cost minimized in geometry pipelines.
SLAM P3
Simultaneous Localization and Mapping: incrementally building a map of an unknown environment while tracking the sensor's pose within it in real time.
Stereo rectification P3
Warping a stereo pair so corresponding epipolar lines become horizontal and aligned, reducing correspondence search to scanning the same image row.
Structure from Motion (SfM) P3
Reconstructing 3D structure and camera poses from an unordered set of overlapping 2D images, typically offline and globally optimized.
Triangulation P3
Recovering a 3D point by intersecting the rays back-projected from its matching observations in two or more calibrated views.
Anchor box P4
Predefined reference boxes of various scales/aspect ratios placed across a feature map; detectors predict offsets and class scores relative to them.
Data augmentation P4
Synthetically expanding training data with label-preserving transforms (flips, crops, color jitter, mosaic) to improve generalization.
IoU (Intersection over Union) P4
Overlap metric for two boxes/masks: area of intersection divided by area of union; 1.0 is perfect, and it gates detection matches.
mAP (mean Average Precision) P4
The mean over classes of Average Precision (area under the precision-recall curve), the standard summary metric for object detectors.
NMS (Non-Maximum Suppression) P4
Post-processing that removes duplicate detections by keeping the highest-scoring box and discarding others whose IoU with it exceeds a threshold.
Pooling P4
A downsampling operation (max or average over a window) that reduces spatial resolution, adds translation tolerance, and cuts computation.
Receptive field P4
The region of the input image that influences a particular neuron's activation; it grows with depth, stride, and dilation in a CNN.
Semantic vs instance segmentation P4
Semantic segmentation labels every pixel by class; instance segmentation additionally separates individual objects of the same class.
Skip (residual) connection P4
A shortcut that adds a layer's input to its output, easing gradient flow and enabling very deep networks like ResNet.
Transfer learning P4
Reusing a network pre-trained on a large dataset (e.g. ImageNet) and adapting it to a new task by fine-tuning, drastically cutting data and compute needs.
CLIP P5
Contrastive Language-Image Pre-training: jointly trains image and text encoders so matching pairs align in a shared space, enabling zero-shot recognition.
Diffusion model P5
A generative model that learns to reverse a gradual noising process, denoising random noise into a sample over many steps (e.g. DDPM, Stable Diffusion).
NeRF P5
Neural Radiance Field: an MLP that maps 3D position and view direction to color and density, rendered via volume integration to synthesize novel views.
ONNX P5
Open Neural Network Exchange: a framework-agnostic model format that lets you export from PyTorch/TF and run via optimized runtimes across hardware.
Patch embedding P5
Splitting an image into fixed-size patches and linearly projecting each into a token vector, the input step that lets a Vision Transformer process images.
Quantization P5
Reducing the numeric precision of weights/activations (e.g. FP32 to INT8 or FP16) to shrink model size and speed up inference, often on edge devices.
Self-attention P5
A mechanism where each token computes a weighted combination of all tokens via query-key-value scores, capturing long-range, content-dependent relationships.
Vision Transformer (ViT) P5
An image classifier that applies a standard transformer encoder to a sequence of patch embeddings plus positional encodings, no convolutions required.

❓ Frequently Asked Questions

Prerequisites, math, hardware, timelines, and how to actually use this roadmap

What prerequisites do I need before starting this roadmap?

Comfort with Python and basic programming, plus high-school-level math. Everything else (linear algebra, calculus, image processing) is built up in Phase 1, so you can start as a motivated beginner. Familiarity with NumPy helps but is taught as you go.

How much math do I really need?

Less than people fear, but it is unavoidable. You need vectors, matrices, dot products, and eigenvectors (for PCA and corner/geometry math), partial derivatives and the chain rule (for backprop), and basic probability. Multi-view geometry leans hardest on linear algebra. You do not need to derive everything from scratch, but you should be able to read the equations.

Do I need a GPU?

Not for Phases 1-3. Classical CV and multi-view geometry run fine on a CPU laptop. For Phase 4 (deep learning) a GPU helps a lot for training, but you can use free cloud GPUs (Google Colab, Kaggle Notebooks) instead of buying hardware. Inference and fine-tuning small models are often CPU-feasible.

How long does the whole roadmap take?

Roughly 6-9 months part-time at a steady pace. The repo budgets about 4-6 weeks for Foundations, 4-5 for Classical CV, several weeks for Multi-View Geometry & 3D Vision, 6-8 for Deep Learning, and 5-7 for Modern Frontiers. Going faster is possible full-time; going slower is fine if you build the milestone projects.

Should I learn PyTorch or TensorFlow?

Start with PyTorch. It dominates research, most new CV papers and repos ship PyTorch code, and its eager execution is easier to debug while learning. TensorFlow/Keras is still common in production and edge (TFLite), so pick it up later if a job or deployment target needs it. The concepts transfer; the syntax is secondary.

Is classical computer vision still worth learning in the deep learning era?

Yes. Multi-view geometry, calibration, feature matching, and filtering power SLAM, AR/VR, robotics, photogrammetry, and the data pipelines feeding neural nets. Classical methods are interpretable, run without GPUs, need no training data, and frequently outperform learned methods on geometric tasks. Interviewers also probe these fundamentals heavily.

How should I actually use this roadmap?

Go phase by phase and treat the milestone project as the gate: do not advance until you have built it. Read or watch one curated resource per topic, code along, then implement the project from scratch (e.g. filters in NumPy before OpenCV). Use the quizzes for self-checks and the interview bank once you are job-hunting. Progress is saved in the interactive site via localStorage.

Do I need to memorize papers and architectures?

No. Understand the key ideas (why ResNet uses skip connections, what attention computes, how RANSAC rejects outliers) rather than memorizing layer counts. Be able to explain trade-offs and implement core pieces (IoU, NMS, a convolution). Depth of understanding on a few things beats shallow recall of many.

What jobs does this roadmap lead to?

Computer Vision Engineer, ML/Deep Learning Engineer (vision), Perception Engineer (robotics/autonomous vehicles), AR/VR or SLAM engineer, Research Engineer, and Edge/Embedded AI roles. The geometry phase opens robotics and AR doors; the deep learning and frontiers phases open detection, segmentation, and generative/multimodal roles. Many start adjacent (data/ML engineering) and specialize.

I already know some deep learning. Can I skip the early phases?

Skim them, but do not fully skip. Many strong DL practitioners are weak on geometry and classical CV, which is exactly where interviews and real perception systems expose gaps. At minimum, do the Classical CV and Multi-View Geometry milestone projects; they teach intuition that pure DL courses omit.
